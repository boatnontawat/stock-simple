# ระบบคลังเวชภัณฑ์ (เวอร์ชันง่าย) — โปรเจกต์ Laravel 11 เต็มรูปแบบ

ตัดความซับซ้อนเรื่องแผนจัดซื้อ/ใบสั่งซื้อ/lot/ledger ออกทั้งหมด เหลือแค่สิ่งที่ต้องใช้จริง:
รายการ, ราคา, มีทั้งหมด, ใช้ไป, คงเหลือ, % คงเหลือ, ใครเช็คล่าสุด

**zip นี้คือโปรเจกต์ Laravel 11 ตัวเต็ม** (ดึงโครง skeleton จริงจาก GitHub ของ Laravel
มาให้แล้ว ไม่ใช่แค่ไฟล์เดี่ยวๆ ที่ต้องเอาไปแปะเองอีกต่อไป) มีครบ `composer.json`,
`artisan`, `bootstrap/`, `config/`, `public/index.php` ฯลฯ **สิ่งเดียวที่ยังไม่มีคือโฟลเดอร์
`vendor/`** (ตัวไลบรารีจริงของ Laravel framework) เพราะเครื่องมือของผมไม่มีสิทธิ์เข้าถึง
Packagist ให้ดาวน์โหลดให้ — ต้องรัน `composer install` เองอีก 1 คำสั่งตามด้านล่าง
(ใช้เวลาไม่ถึงนาทีถ้าเน็ตเร็ว)

## วิธีติดตั้ง (รันได้จริงตั้งแต่ต้นจนจบ)

```bash
# 1) แตก zip แล้วเข้าไปในโฟลเดอร์
cd stock-simple

# 2) ติดตั้ง dependency ของ Laravel (ต้องมี PHP >= 8.2 และ Composer)
composer install

# 3) ตั้งค่า .env และสร้าง APP_KEY
cp .env.example .env
php artisan key:generate

# 4) สร้างตารางฐานข้อมูล (ค่าเริ่มต้นใช้ SQLite ไฟล์เดียว ไม่ต้องติดตั้ง MySQL ก่อนก็ทดสอบได้เลย)
php artisan migrate

# 5) นำเข้าข้อมูลจริง 91 รายการจากไฟล์ Excel แผนจัดซื้อฯ
php artisan db:seed

# 6) รันเซิร์ฟเวอร์ทดสอบ
php artisan serve
```

จากนั้นเปิด `http://127.0.0.1:8000` ได้เลย (จะ redirect ไปหน้า `/stock-items` ให้อัตโนมัติ)

### ถ้าจะต่อ TiDB Cloud แทน SQLite (ตาม pattern ที่ใช้ในโปรเจกต์อื่นของคุณ)

แก้ไฟล์ `.env` เปลี่ยน `DB_CONNECTION=sqlite` เป็นชุดค่า TiDB (มีเทมเพลตคอมเมนต์ไว้ให้
ในไฟล์แล้ว) แล้วรัน `php artisan migrate` ใหม่อีกครั้ง

## ข้อมูลที่ seed มาจากไฟล์ Excel

นำเข้าจาก "แผนจัดซื้อจัดหาเวชภัณฑ์ที่มิใช่ยา หน่วยจ่ายกลาง ปี 2569" ที่แนบมา รวม
**91 รายการ** (87 รายการจากแผนหลัก + 4 รายการจากหมวด "ขอจัดซื้อเพิ่มเติมเนื่องจาก
หมุนเวียนใช้ไม่เพียงพอ") การแมปคอลัมน์เป็นแบบนี้:

| คอลัมน์ในไฟล์ Excel | → | ฟิลด์ใน `stock_items` |
|---|---|---|
| รายการ | → | `name` |
| หน่วย | → | `unit` |
| ราคาต่อหน่วย | → | `price` |
| จำนวนที่ต้องการ | → | `stock_qty` (ใช้เป็นจำนวนตั้งต้น) |
| — (ไม่มีข้อมูล) | → | `used_qty` = 0 ทุกรายการ |
| — (ไม่มีข้อมูล) | → | `checked_by` / `checked_at` = ว่าง |

**ข้อควรทราบ:** "จำนวนที่ต้องการ" ในไฟล์คือยอดที่ *ขอจัดซื้อ* สำหรับทั้งปี ไม่ใช่ยอด
คงคลังจริงที่มีอยู่ตอนนี้ ถ้าคลังจริงมีของเหลืออยู่แล้วหรือมีการใช้ไปบ้างแล้ว ควรเข้าไป
แก้ `stock_qty`/`used_qty` ให้ตรงกับของจริงอีกครั้งหลัง seed (แก้ทีละรายการที่หน้าเว็บ
ได้เลย ไม่ต้องรัน seeder ใหม่) คอลัมน์ "เหตุผลและความจำเป็น" ในไฟล์ไม่ได้นำเข้ามาด้วย
เพราะตารางแบบง่ายนี้ไม่มีช่องเก็บข้อมูลนั้น

## หลักการทำงาน

- **คงเหลือ** และ **% คงเหลือ** ไม่ได้เก็บเป็นคอลัมน์ในฐานข้อมูล แต่คำนวณสดทุกครั้งใน
  `StockItem` model จาก `stock_qty - used_qty` — ข้อดีคือตัวเลขจะตรงกันเสมอ ไม่มีปัญหา
  "คงเหลือ" กับ "มีทั้งหมด - ใช้ไป" ไม่ตรงกันจากการแก้ไขคนละจุด
- แถบสีในหน้ารายการ: **เขียว** (>50% เหลือ), **เหลือง** (20-50%), **แดง** (≤20%)
  ปรับเกณฑ์ได้ที่ตัวแปร `$barColor`/`$textColor` ใน `resources/views/stock-items/index.blade.php`
- ฟอร์มมี validation กันกรอก "ใช้ไป" มากกว่า "มีทั้งหมด" (จะได้ไม่มีคงเหลือติดลบ)
- `checked_by` เป็นช่องกรอกชื่อธรรมดา (ไม่ผูกกับระบบ login) เพื่อให้ใช้งานได้ทันทีโดยไม่ต้อง
  ตั้งค่าระบบสมาชิกก่อน — ถ้าภายหลังมีระบบ login แล้วอยากผูกกับ user จริง บอกได้เลย
- ยังไม่มีการล็อกอิน/สิทธิ์ผู้ใช้งานในเวอร์ชันนี้ — ถ้าต้องการจำกัดว่าใครเข้าหน้านี้ได้บ้าง
  มีคอมเมนต์ตัวอย่างไว้ในไฟล์ `routes/web.php` แล้ว

## ถ้าอยากได้เพิ่มภายหลัง (ไม่ได้ทำตอนนี้)

- ปุ่ม "+ บันทึกการใช้วันนี้" แยกจากหน้าแก้ไข จะได้ไม่ต้องเปิดฟอร์มเต็มทุกครั้งที่มีการเบิกใช้
- ประวัติการเช็คสต๊อกย้อนหลัง (ตอนนี้เก็บแค่ค่าล่าสุด ทับของเก่า)
- แจ้งเตือนอัตโนมัติ (LINE Notify/อีเมล) เมื่อ % คงเหลือต่ำกว่าเกณฑ์ที่ตั้งไว้
